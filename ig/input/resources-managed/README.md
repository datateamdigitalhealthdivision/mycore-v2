# Managed resources

This directory holds **owned, authored terminology** — content this team maintains directly or
publishes from TermX. It is the counterpart to `../resources/`, and the split is deliberate.

| Directory | Contents | Regenerated? |
|---|---|---|
| `../resources/` | Output of `scripts/migrate-legacy-assets.py` — the legacy MY Core migration | **Yes.** Every `*.json` there is deleted and rewritten on every build |
| `resources-managed/` (this one) | Malaysian Pathology Catalogue, and future TermX-pushed terminology | **No.** Nothing regenerates or deletes these files |

## Why the split exists

`migrate-legacy-assets.py` begins each run with:

```python
for path in DEST_ROOT.glob('*.json'):
    path.unlink()
```

`DEST_ROOT` is `ig/input/resources`. Any hand-authored or TermX-published resource placed there
would be **silently deleted on the next build**. This directory is outside that path, is never
referenced by the migration script, and is therefore safe.

The migration script is scoped to `../resources/` only, by design. Do not widen it.

## Build inclusion

Both directories are listed under `parameters.path-resource` in `sushi-config.yaml`, so the IG
Publisher picks up both. Adding a new managed subdirectory requires its own `path-resource` entry —
the Publisher does not recurse.
