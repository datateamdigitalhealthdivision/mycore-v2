# MY Core Authoring Model

MY Core v2 uses three computable resource streams so generated content is separated from human-owned content.

## Streams

- `ig/input/resources-legacy-migrated/` contains legacy-derived resources regenerated by the migration script. This directory is disposable and may be wiped and rebuilt during a fresh migration run.
- `ig/input/resources-forge/` contains human-owned Forge-authored resources such as `StructureDefinition`, extensions, `SearchParameter`, `Questionnaire`, and related conformance artefacts. The build never wipes this directory.
- `ig/input/resources-terminology/` contains human-owned MY Core terminology artefacts such as `CodeSystem`, `ValueSet`, and `ConceptMap`. The build never wipes this directory. International terminologies such as SNOMED CT, LOINC, ICD, RadLex, and UCUM are managed outside this folder and must not be copied into the repository.

## Ownership Rules

- Generated legacy content remains traceable to `source/` and is refreshed only through the migration script.
- Human-maintained profile content is edited in Forge against the local git checkout and committed through normal repository review.
- Human-maintained terminology content is edited as JSON in the terminology stream and committed through normal repository review.
- The collision audit is a hard build gate. If the same resource id or canonical URL appears in more than one stream, the build fails until ownership is resolved.

## Promotion Path

The intended promotion path is gradual:

1. A resource begins life in `resources-legacy-migrated/` as migration output.
2. When the team decides to actively maintain that resource, move the JSON into `resources-forge/` or `resources-terminology/`, depending on the artefact type.
3. Once moved, the human-owned copy becomes the authoritative source and can be edited safely without the migration wiping it.
4. The collision audit prevents the same artefact from being published from two streams at once.

This model allows MY Core to move from migration-first maintenance toward sustainable authoring one artefact at a time without changing canonical URLs or published package identity.
